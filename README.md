# GharDekho

GharDekho is a production-oriented Indian real-estate marketplace in an npm workspace monorepo. The web app and future mobile clients use the same versioned Fastify API; PostgreSQL is the source of truth.

## Architecture

```text
apps/
  web/                  Next.js App Router, TypeScript, Tailwind CSS
  api/                  Fastify REST API, sessions, property endpoints
packages/
  database/             Prisma schema, migrations and development seed
  validation/           Shared Zod request schemas
  types/                Shared API/domain TypeScript contracts
```

- The browser calls the API using `NEXT_PUBLIC_API_URL`; it is not a private secret.
- Passwords are hashed with bcrypt. The API issues an opaque, random session in an HTTP-only cookie and stores only a keyed hash of the token in PostgreSQL. Logout revokes the session row.
- PostgreSQL owns users, profiles, sessions, property listings, media metadata, amenities, favorites, inquiries and visit requests.
- Property photos/videos are metadata URLs only at this stage. File storage/upload integration is a later phase.
- There are no fabricated property API results or mock authentication flows in the running application.

## Requirements

- Node.js 20.9 or newer
- npm 10 or newer
- PostgreSQL 16 or newer

## Local setup

From the repository root:

```sh
cp .env.example .env
npm ci
```

Set a unique development `AUTH_SECRET` (at least 32 characters) and a reachable `DATABASE_URL` in `.env`. For example, generate a secret with `openssl rand -base64 48`.

`DATABASE_URL` uses the PostgreSQL connection-string format:

```text
postgresql://USER:PASSWORD@HOST:5432/DATABASE?schema=public
```

If you use Docker locally, a disposable development database can be started with:

```sh
docker run --name ghardekho-postgres \
  -e POSTGRES_DB=ghardekho \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=ghardekho_local_dev \
  -p 5432:5432 \
  -v ghardekho-postgres-data:/var/lib/postgresql/data \
  -d postgres:16-alpine
```

For that local-only example, set `DATABASE_URL=postgresql://postgres:ghardekho_local_dev@localhost:5432/ghardekho?schema=public`. Do not reuse the sample password in a deployed environment.

## Database and migrations

Prisma Client is generated by the database workspace during `npm ci` and by database build commands.

```sh
npm run validate --workspace @ghardekho/database
npm run migrate:deploy --workspace @ghardekho/database
```

When changing the schema during development, create a reviewed migration:

```sh
npm run migrate:dev --workspace @ghardekho/database -- --name describe_the_change
```

Production deployments use `prisma migrate deploy`; never use `prisma db push` in production. Migrations apply incrementally and do not reset production data.

## Development seed

The seed creates three explicitly named development accounts, eight amenities and three clearly marked sample listings. It refuses to run without credentials supplied through the environment. Set these variables in `.env` before seeding:

```text
SUPER_ADMIN_EMAIL=super-admin@dev.ghardekho.local
SUPER_ADMIN_PASSWORD=<unique development password, at least 12 characters>
ADMIN_EMAIL=admin@dev.ghardekho.local
ADMIN_PASSWORD=<unique development password, at least 12 characters>
USER_EMAIL=user@dev.ghardekho.local
USER_PASSWORD=<unique development password, at least 12 characters>
```

Then run:

```sh
npm run seed --workspace @ghardekho/database
```

These are development-only records. Do not put real credentials in source control or reuse seed passwords.

## Run the apps

Set `NEXT_PUBLIC_API_URL=http://localhost:4000` and `WEB_ORIGINS=http://localhost:3000` in `.env`.

In separate terminals:

```sh
npm run dev:web
```

```sh
npm run dev:api
```

The web app runs at `http://localhost:3000`; the API runs at `http://localhost:4000`. The API starts independently, and database-backed endpoints require the configured PostgreSQL service and migrations.

## API

All business endpoints use the `/api/v1` prefix. Responses use `{ success, data }`; list endpoints also include pagination. Errors use `{ success: false, error: { code, message } }` without exposing stack traces or database details.

| Method | Path | Access | Purpose |
|---|---|---|---|
| GET | `/health` | Public | Liveness response `{ "status": "ok" }` |
| POST | `/api/v1/auth/register` | Public, rate limited | Register and create a session |
| POST | `/api/v1/auth/login` | Public, rate limited | Verify password and create a session |
| POST | `/api/v1/auth/logout` | Session | Revoke the active session |
| GET | `/api/v1/auth/me` | Session | Return the signed-in user's public profile |
| GET | `/api/v1/properties` | Public | Paginated, published-property search |
| GET | `/api/v1/properties/:id` | Public/session | Published listing, or own/admin listing |
| POST | `/api/v1/properties` | Session | Create a draft listing |
| PATCH | `/api/v1/properties/:id` | Owner/admin | Update a listing; owner edits return to review |
| DELETE | `/api/v1/properties/:id` | Owner/admin | Archive a listing without hard deletion |
| POST | `/api/v1/properties/:id/inquiries` | Session | Contact a published listing's owner |
| POST | `/api/v1/properties/:id/visits` | Session | Request a visit to a published listing |

Property search supports `city`, `locality`, `propertyType`, `listingType`, `minPrice`, `maxPrice`, `bedrooms`, `furnishing`, `page`, `limit` and `sort` (`newest`, `price_asc`, `price_desc`, `area`). Only `PUBLISHED` listings appear in public search.

## API client boundary

Shared contracts and schemas live in `packages/types` and `packages/validation`. The Next.js app has API modules in `apps/web/lib/api/` for session auth and properties. Requests include browser credentials for the HTTP-only cookie; no session token is exposed to frontend JavaScript. The existing homepage remains a marketing page and does not make fake listing requests.

## Quality checks

```sh
npm ci
npm run lint
npm run typecheck
npm run test:api
npm run test:api:integration
npm run build
```

The fast API suite covers health, registration/login/logout, session privacy, property ownership, unauthenticated writes, and public filtering with an injected test database adapter. `npm run test:api:integration` requires a migrated PostgreSQL database and exercises the live Prisma-backed routes. `npm run build` builds the shared packages, API and web app.

## Environment variables

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string |
| `PORT` | API port (defaults to `4000`) |
| `NODE_ENV` | Runtime mode |
| `AUTH_SECRET` | HMAC key for stored session-token hashes; configure a unique 32+ character value |
| `WEB_ORIGINS` | Comma-separated exact browser origins allowed by CORS/CSRF checks |
| `COOKIE_DOMAIN` | Optional cookie domain; leave unset for local development |
| `NEXT_PUBLIC_API_URL` | Browser-visible API base URL; local `http://localhost:4000`, production `https://api.ghardekho.tech` |
| `SUPER_ADMIN_EMAIL`, `SUPER_ADMIN_PASSWORD` | Development seed only |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Development seed only |
| `USER_EMAIL`, `USER_PASSWORD` | Development seed only |

`.env`, `.env.local`, `.env.production`, and `.env.*.local` are ignored by Git. `.env.example` is safe to commit and contains placeholders only.

## Troubleshooting

- **Prisma cannot connect:** verify PostgreSQL is running, the database exists, the username/password are correct, and reserved URL characters in the password are percent-encoded.
- **Migration reports authentication failure:** check `DATABASE_URL` in the current shell or `.env`; never work around this by resetting an existing database.
- **Browser request is blocked:** ensure `WEB_ORIGINS` exactly matches the frontend origin, including scheme and port. Credentialed CORS cannot use `*`.
- **Seed refuses to run:** set all six development account variables; passwords must be at least 12 characters.
- **API starts but database routes fail:** run the migration command and verify the API process received the same `DATABASE_URL`.
